# Native foundation review

2026-09-23. Independent source review of the current validation foundation, refreshed against the Onn local-media hardware result. This review is not whole-product physical acceptance. The lead owns device testing; source inspection and structural guards cannot certify installed behavior.

## Findings and disposition

1. Android import retains bytes, decodes a first frame from the retained URI, checks duration, and cleans failed or superseded private copies (`MainActivity.kt:129-194`, `LocalVideo.kt:15-122`). The Onn harness passed valid/invalid import, repeat import, and a changing-provider case that deliberately starts with a stale Activity core while preserving a newer profile position. A first frame still cannot certify sustained playback, audio, subtitles, or the rest of a file; interrupted writes and storage-failure rollback remain untested.
2. Saved titles can be removed from Library after a source becomes unavailable (`NativeScreen.kt:224-264`). The Onn harness verified core save/revoke/remove and profile-separated positions, but it did not exercise the visible Library control or profile switching in the UI.
3. Picker-less TV has a source-level route through a consented `ACTION_VIEW` video intent (`AndroidManifest.xml:7-12`, `MainActivity.kt:103-116`). The hardware harness invokes the private import method, so a separate lead-operated ACTION_VIEW check observed the real consent dialog and Back dismissal on the TV. External source-app handoff, permission lifetime, and D-pad confirmation remain unverified.
4. Shared buttons use one clickable focus target with button semantics (`NativeScreen.kt:278-291`). Physical D-pad traversal, focus contrast, Select, Back, and first-run UI completion still require journey testing.

The current shared UI exposes a thin onboarding, Home, saved Library, and Settings placeholder. Remaining feature groups and UI acceptance IDs are a single foundation-scope gap, not individually accepted or rejected by this review. No current finding establishes PIN/family security because those flows are not implemented in this slice. Android validation retains a separate package, no Internet permission, and a non-exported player.

## Installed local intelligence pack — bounded reuse assessment

The canonical `architecture:report` currently lists **11 registered** capabilities: seven deterministic fallback and four shadow. An installed private pack at `C:/Users/austi/Documents/Codex/2026-09-19/i-h/work/tools/reelos-intelligence` contains Qwen2.5-1.5B-Instruct Q4_K_M GGUF (1,117,320,736 bytes; SHA-256 `6a1a2eb6d15622bf3c96857206351ba97e1af16c30d7a74ee38970e434e9407e`, verified locally) and llama.cpp `b11065` Windows CPU x64 runtime. The local receipt pins Qwen revision `91cad51170dc346986eccefdc2dd33a9da36ead9`, lists Apache-2.0/MIT notices, and explicitly marks both pieces downloaded/installed **but not registered or activated**. GGUF v3 metadata identifies architecture `qwen2`, name `qwen2.5-1.5b-instruct`, 28 blocks, context 32,768, and `qwen2.embedding_length = 1536` (transformer hidden width). It is not an evaluated 512-dimensional Float32 media embedding, taste model, or proof of semantic retrieval quality.

The pack can potentially be reused without downloading bytes for a bounded **Windows-only local language experiment**, such as shadow natural-language query interpretation. Reuse still needs a separately signed artifact manifest, verified/evaluated model set, a compatible worker adapter and output contract, resource budget, and OS-enforced network isolation. The existing JavaScript artifact registry and executor require those gates (`scripts/services/model-artifact-registry.mjs`, `local-model-executor.mjs`); its generic process adapter expects JSON-line specialist input/output, which the installed `llama-cli.exe` does not itself establish. The install receipt alone cannot activate the pack. The bundled runtime is Windows x64 only and has no demonstrated Android TV, Fold, or Linux execution path. The current Kotlin native core has no learned-vector schema, feature/event store, model registry, inference worker, coordinator route, or model result path into the shared UI (`clients/native/CORE-CONTRACT.md:53-56`). The isolated Android preview has no Internet permission, but that alone does not establish a general network-isolated model-worker boundary.

Recommended next slice: define one versioned local inference request/result contract for `semantic-search` in shared Kotlin, with profile scope, cancellation/deadline, deterministic fallback, and no credentials or learning export; evaluate the cached Qwen pack only as a shadow language candidate on Windows. Keep the 512D Float32 embedding requirement separate until an actual learned embedding artifact and quality baseline exist. The canonical `shared-taste-intelligence` shadow metadata now describes authorized within-Home matching and no cross-Home learning export. The legacy executor now rejects `export_candidate` before runtime eligibility or execution; 16 targeted tests pass, including rejection without adapter calls. This does not authenticate Home membership, prove OS-level network isolation, or activate a model. The signed-manifest, evaluation, adapter, resource, and network-isolation gates remain blocked for this native slice; the cached artifact avoids a download but satisfies none of those gates.

## Current native hardware evidence and limits

The Onn 4K Pro record `.reelos-audit/native-hardware/192.168.1.95_5555/result.json` (2026-09-23T13:06:53Z) reports **10/10 passed, zero skips** for local native media integration on the isolated validation package. The app and test APK hashes are recorded there; every listed current Android source, test, fixture, manifest, and build file hash matches the record. The cases cover valid/invalid local import, private-copy replacement, first decoded frame, keep-awake while playing and paused, seek/persist/resume, completed-title restart, a changing content provider with a deliberately stale Activity snapshot, and core profile separation/source revocation. The harness uses a generated 30-second silent video and direct import invocation. It does not certify UI onboarding, ACTION_VIEW consent, remote traversal, audio/subtitles, sustained films, background behavior, or full product acceptance.

The player captures the launch profile for writes, pauses in `onStop`, stores zero at `STATE_ENDED`, and reloads current core state for bounded stale-revision retry (`PlaybackActivity.kt:34-99`). The Onn checks verify position persistence, resume, completed-title restart, and keep-awake state on this fixture. The Android import similarly reloads current core state for its write and refreshes the UI after asynchronous success (`MainActivity.kt:49-65,129-194`). Other shared presentation mutations can still use a captured core after a player write and need a coordinated reload/retry policy. A failed position write in `onStop` still needs a visible durable status path.

The Windows lead separately confirmed native rendering, pause, seek, replay, and normal process exit on a stable run. Earlier class-loading failures occurred while the live classpath was being recompiled; they do not establish a native shutdown defect. This is narrower than installed Windows release acceptance and does not establish Fold or HP behavior.
