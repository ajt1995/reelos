# Optional shared provider API

`com.reelos.providers` is a standalone Kotlin/JVM TorBox protocol adapter for Android and desktop hosts. It does not depend on the Node services or the shared product core. The host supplies a credential from its platform vault and rechecks the vault's current credential revision/authorization before and after calls; the adapter does not store keys, authorize playback bytes, acquire torrents, or delete provider data.

`validate(secret)` returns a stable provider account ID. Native browsing uses `page(secret, expectedAccount, offset)`: 25 torrent records per request, with a continuation rather than a library-size cap. Files inside a pack remain individually selectable. Readiness requires Boolean `download_finished` and `download_present`; a status label is insufficient. `resolve` revalidates the account and exact torrent/hash/file/name/size binding and readiness, returning an opaque lease.

The provider documents `requestdl` with a token query, and an actual provider-issued CDN lease may also embed the credential. These are unavoidable protocol exceptions, not permission to expose the URL: the fixed API transport disables redirects and logs no raw request/response/exception. `ProviderStream.openBytes` gives hosts guarded bytes; its URI accessor is internal to this module. Credential-bearing leases are accepted only on HTTPS TorBox-controlled domain names and their redirect chain is restricted to that domain. Never pass lease URLs to players, intents, profile/core state, logs, models, exports or remote clients. Do not enable HTTP wire logging. JVM immutable strings cannot promise perfect memory zeroization.

Intentional budgets: each collection/exact-file response is at most 2 MiB, account/lease responses 256 KiB, JSON depth 24 and nodes 160,000; requests have connection/read/body deadlines. The measured 25-entry page was 284,025 characters / 451 files, exceeding the former inappropriate 256 KiB collection limit. Cached browsing respects provider load; exact resolution refreshes authority. Oversized individual pages fail honestly; do not silently omit files. The bulk compatibility API has a 20,000-file/60-second memory/work budget, but native UI uses continuations and resume lookup walks pages without retaining them all. There is no total 1,000-entry UI cutoff or inaccessible 40-file tail.

Android Keystore and Windows current-user DPAPI protect credentials. Credential replacement/removal invalidates prior source scopes; old source projections are revoked without deleting personal originals. Linux protected storage remains unavailable, not plaintext. The current isolated native validation build includes this optional adapter directly and remains release-blocked; it is not proof of sanitized public packaging.

Verification is incremental: live account, exact-file resolution and 16 KiB ranged bytes passed on the owner's Fold. Actual remote movie decoding/sustained playback remains unverified. Tests use synthetic credentials or borrow the protected key only inside the explicitly authorized device test. Diagnostics contain fixed codes, schema counts, Boolean comparisons and a non-secret CDN hostname, never account/media/key values or full URLs. Physical connection-store tests passed on Fold, Pixel and Onn TV. Consult source-fingerprinted local evidence for current results; these are not full release acceptance.
